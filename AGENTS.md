# ScalarPitchfork agent guidance

Read README.md (What is proved, Not proved here, Trust and axioms) before you edit. Check `git status` first and keep
other contributors' uncommitted work.

## Authority

1. The Lean declaration decides every hypothesis and quantifier.
2. `claims.yaml` lists the reusable claims. The comparator configurations (`comparator.json`,
   `comparator.headline.json`) list the statements that were compared.
3. The generated verification block in README.md and the receipts under `.lean-receipts/` record what was
   checked and at which commit. A receipt covers only the content it names.
4. Prose in README.md and docs/ describes the results. Lean does not check it.

## Scope

The library starts from the scalar normal form `alpha * tau * z - beta * z ^ 3 + R tau z`. It has no
Crandall–Rabinowitz theorem, no center-manifold or Lyapunov–Schmidt reduction, no degree theory (no
Leray–Schauder degree, no Rabinowitz global alternative), no certified-root tools and no PDE theory. The
global part is the topological skeleton only: the global alternatives are hypotheses. Do not describe any
of these as proved.

## Working rules

- Use the pinned `lean-toolchain` and `lake-manifest.json` together. Never run `lake update` in this
  repository during a verification run.
- Compile changed modules locally before starting a long verification run.
- Keep the Lean source, `claims.yaml`, the comparator configurations, `HeadlineChallenge.lean`, the README
  headline list and `coverage.yaml` in step. A renamed or weakened theorem must change all of them.
- Do not strengthen a theorem in prose. Keep `0 < alpha`, `beta ≠ 0`, `0 < r ≤ 1`, the side condition
  `0 < tau * beta`, the radius `|z| ≤ ρ`, "for all small `tau`" and the continuity of `R` in `tau` (for the
  branch curves) visible wherever a result is described.
- The only permitted axioms are `propext`, `Quot.sound` and `Classical.choice`. No `sorry`, `axiom`,
  `opaque` or `native_decide` in the library modules (the Challenge files and the disabled negative
  controls are the only exceptions, by design).
- Never fabricate a receipt, and never let a receipt for one commit stand for changed source.
- Keep private paths, unpublished drafts and internal process names out of the repository and its history.
- No GitHub Actions workflows. `docs/verification.md` and `docs/coverage.md` are generated by
  `lean-pkg page --site docs`; never edit them by hand, and never hand-write the README block between the
  `lean-pkg:page` markers or a computing acknowledgment (`lean-pkg page` generates it from the recorded receipts).
